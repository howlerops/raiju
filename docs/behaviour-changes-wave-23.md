# Behaviour changes in wave 23

Wave 23 (L174 to L187) combined production hardening with the parity work packages. These changes can affect an existing deployment; most match Bifrost's behaviour or the owner decisions in HANDOFF.md.

- **L175**: GET /api/agents/history answers Bifrost's {logs, pagination} shape (was {history, total}); PUT /api/plugins/{name} merges the body's config over the stored one by top-level key (send null to remove a key); attaching a virtual MCP to a key whose owner holds an access profile is 409; built-in roles are editable (the admin role must keep RBAC View and Update).
- **L185**: A relative logs_store or audit dir is read from the config file's folder (not the working directory); an enabled log or audit store whose folder cannot be written fails the start (logs_store.required / audit.required: false restores the old behaviour); management API answers on a multi-worker node wait up to 2 s for the other workers to apply the change; new cluster.config_sync (file, pull, off).
- **L186**: Outbound URLs are checked with canonical IP parsing and a connect-time DNS check (private and metadata targets refused unless allowed); webhooks, card fetches and exporters no longer follow redirects; provider base_url saves via the API are validated (private needs network_config.allow_private_network); plugin URLs must be https unless pinned by sha256; the plugin cache moved to <config dir>/plugin-cache (0700).
- **L184**: /api is locked with no admin and no setup token (403; setup_token or BIFROST_SETUP_TOKEN opens the setup flow); the default bind is 127.0.0.1 (BIFROST_HOST or -host to change; Docker, helm and ECS pass 0.0.0.0); a virtual key with no mcp_configs gets no MCP tools (only allow_by_default clients); realtime WebRTC calls need server.webrtc_enabled; async job polls are checked against the submitting key or credential; secret-bearing files are 0600 and state folders 0700; the share folder is $TMPDIR/raiju-<pid>-<random>; metric labels are bounded; the ECS module needs ingress_cidr_blocks and certificate_arn (or allow_plain_http).
- **L176**: A2A grant refusals on JSON-RPC are 200 with error -31403 and an ErrorInfo (REST 403 PERMISSION_DENIED, gRPC PERMISSION_DENIED; the card route plain "Forbidden"), as Bifrost; post_builtin plugins (the default, incl. mocker and blocklist) run their pre hooks after governance, budgets and the cache lookup.
- **L177**: Streamed Responses requests no longer run the MCP agent/code-mode loop: the stream is served live and tool calls go to the caller, as Bifrost does.
- **L180**: jwt_bearer oauth keys need issuer and audience (no fallback to client_id and the token URL) and are validated on save; load_balancer_config.enabled turns adaptive balancing on and providers are ranked by measured performance; provider model listings are cached for live_models_sync_interval (default 1 h) and refreshed in the background; adaptive holds and incidents survive restarts (<config>.adaptive.json).
- **L181**: OpenAI-family, Gemma 4 and Grok models on a Bedrock key go to the Mantle surface, as Bifrost; a scim_config with a provider (and no oidc role_map/default_role) applies Bifrost's claim-sync rules at sign-in (no default role); oidc.redirect_uri is optional.
- **L179**: `client.enforce_vk_object_ownership` now defaults to on. Another virtual key's provider file and batch reads, cancels and deletes return 404 `access_blocked`, and lists leave those objects out (as in Bifrost).
