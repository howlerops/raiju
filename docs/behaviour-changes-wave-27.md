# Behaviour changes in wave 27

Wave 27 (L202 to L204) fixed the findings of the third production re-audit (docs/audits/production-reaudit-3-2026-10-25.md).

- **L203**: /oauth2/register is limited per client address and in total (`client.oauth2_server_config`; 429 with Retry-After; set `server.trusted_proxies` behind a proxy); MCP OAuth clients that never got a grant expire after an hour (the oldest are dropped past 1000) and live in a new `mcp-oauth-state-clients.jsonl` (the state file is split at the first start; pending consent requests are dropped); /oauth2/authorize consent links are sealed; OIDC login sets a `raiju_oidc_state` cookie that the callback requires (cookieless callbacks get 401); a clustered gateway without an encryption key derives the OIDC state key from `cluster.secret`.
- **L202**: config changes hold the file lock only around the reread, merge and save; a lock held elsewhere past 15 s answers 503 with Retry-After: 1 and nothing of the change runs (it was 500); routes that make network calls do them first and answer 409 when another change conflicts; saves never sleep for the lock; every lock holder also creates and removes the wave 25 `<file>.lock` directory, so a rolling upgrade from wave 25 serializes with it (the bridge is dropped in a later release; do not mix wave 25 and wave 26 directly).
- **L204**: `server.body_deadline_seconds` now applies only to bodies whose credential was not checked, default 30 s (was 120); authenticated bodies have no fixed deadline but must average `server.body_min_kb_per_second` (32) after `server.body_rate_grace_seconds` (10); unchecked bodies (auth off, plugin HTTP hooks) share `server.unchecked_body_mb` (an eighth of the cap) while other big bodies are in; a big /mcp body is answered 401/404 from the headers before it is read; peer POSTs need the new `x-raiju-cluster-head` and `x-raiju-cluster-ts` headers and have their own budget, so upgrade all of a cluster's nodes together.
