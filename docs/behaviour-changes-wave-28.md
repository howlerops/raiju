# Behaviour changes in wave 28

Wave 28 (L205 to L207) fixed the findings of the fourth production re-audit (docs/audits/production-reaudit-4-2026-10-25.md).

- **L205**: a checked body that sends a lot at once and then trickles is cut a window after its grace (`server.body_rate_window_seconds`, 30; about 40 s by default); checked and peer bodies have a ceiling (`server.body_max_seconds`, 600), so very large uploads over slow links may need it raised; the bytes one credential holds past `server.credential_body_mb` (a quarter of the cap) no longer turn other callers away; configured direct provider keys (allow_direct_keys) get the checked class; the broker refuses POSTs without a signed head and the old constant GET signature, so upgrade brokers and nodes together.
- **L207**: virtual key, team and customer names are unique (409 on a clash, as Bifrost's unique index; duplicates were accepted before); concurrent management writes on a worker are saved as one group (one notice "N changes (...) were saved", one generation); a change that joins a group late shares its wait for the lock; a failed group write answers 500 to every change in the group that would have saved.
- **L206**: MCP OAuth registration stores nothing until a client's first grant: the client_id is a sealed value (about 200 characters) under a key derived from the signing key, so changing the signing key voids not-yet-granted client_ids; registrations are counted per address in `mcp-oauth-state-registrations.jsonl`; clients registered by a wave 27 pod keep working, but the new format is not readable by wave 27, so upgrade stop-first when MCP OAuth is on; Math.random is seeded from getrandom and reseeded in each worker (tov-patches 0021), and entity ids (webhooks, prompts, notices, alert rules) and OTel trace ids come from secureHex; `RAIJU_TRUSTED_PROXIES` sets trusted proxies when `server.trusted_proxies` is not in the config, and the ECS module sets it to the VPC CIDR by default.
