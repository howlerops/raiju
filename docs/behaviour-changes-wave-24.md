# Behaviour changes in wave 24

Wave 24 (L188 to L194) finished the production follow-ups and most of the remaining parity rows. These changes can affect an existing deployment; most match Bifrost's behaviour.

- **L188**: a provider base_url on a private address (RFC 1918, cluster-internal) needs `network_config.allow_private_network: true`, for config-file providers too, and is checked at connect time by the runtime (tov-patches 0013), as Bifrost's ConfigureDialer; loopback is still allowed; 0.0.0.0, link-local and metadata addresses are always refused. A2A calls follow same-origin redirects only; OpenAPI tool calls that carry credentials get a cross-host or https-to-http redirect back as the 3xx; MCP OAuth (admin flow, per-user token endpoints) and token-exchange endpoints must be public or listed in `mcp.oauth_private_allowlist`; the MCP library, exporters and vector stores refuse link-local, unspecified and metadata addresses.
- **L191**: SCIM writes keep every user field (synced, claims and budget overrides were dropped before); a SCIM deactivation removes the user's keys, memberships and access profiles but keeps the pushed profile, and reactivation restores the SCIM groups and what the rules give; a SCIM delete also removes the user's keys and project memberships; with mapping rules configured, a pushed `roles` value no longer decides the role (the rules applied to SCIM data do, through claimScimAttributes); the scim-derived oidc section asks for `offline_access` (not for Google) and sign-in sessions keep the IdP refresh token server-side and refresh before management requests; new sign-in users get source "sso"; removing a synced business-unit membership by hand is 409; syncs never remove or demote the last enabled admin.
- **L190**: a Bedrock key with no value and no access/secret key signs with the AWS default chain (profile, environment, IRSA web identity, shared credentials, ECS/Pod Identity, IMDS) instead of sending an empty bearer; a non-streamed inference caller that disconnects cancels the upstream call, with no retries or fallbacks, logged 499; the A2A gRPC binding accepts and answers gzip and upstream gRPC calls advertise it; agents[] client certificates are sent (tov-patches 0015) and a certificate without its key (or the reverse) fails the agent's calls.
- **L192**: MCP identity follows Bifrost's order (user, then virtual key, then session): a request with both a virtual key and x-bf-mcp-session-id is keyed by the key; A2A history lists stream event rows by default (stats and histograms count them unless record_kind is given) and rows carry a request_id; the Maxim exporter sends maxim-go commit-log lines; realtime sessions run plugin LLM hooks per turn and a plugin can close the session; the tool-groups API is scoped by data access control.
- **L193**: a config that sets logs_store.object_storage now offloads every log row's payload to object storage, as Bifrost's hybrid store does (set logs_store.object_storage_offload: false for the old retained-only behaviour); under clustering, log reads include peer nodes' rows by default (cluster.log_reads); inference bodies naming another key's file or cached content get 404 access_blocked; deleting a user removes them from project rosters, and roster or cap changes on equal-split projects queue a redivision job; a row held for a logs_only output check on Presidio or Azure PII is recorded when that check ends.
- **L194**: Hugging Face is a native provider with Bifrost's multi-backend routing (`huggingface/<inference provider>/<hub id>`): embeddings need an inference provider in the model name, the model listing reads the hub, and its files and batches answer 400; Replicate image predictions send `number_of_images` (was num_outputs) and map size to aspect_ratio and resolution, as Bifrost; `ck-bf-agent-` agent tokens are accepted on inference; a REST call under `/agents/a2a/{name}/rest/v1/...` is a v0.3 call.
- **L189**: SIGTERM closes WebSockets with 1001 "server shutting down": UI feed sockets at once, realtime and WebRTC sessions when the drain grace ends (they keep serving until then; Bifrost closes them at the signal), with up to 3 s more before they are cut; broker mode stops gracefully, applies the server.* timeouts and serves /ready; http1 drops a client that stops reading for idle_timeout_seconds; the web UI opens on a setup screen while no admin exists.
